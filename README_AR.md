# خطوات 2.0 — Journey & Growth OS للسعودية

«خطوات» منصة عربية RTL مستقلة تساعد المستخدم على البدء من **الهدف الذي يريد إنجازه** ثم ترتب له الجهات والمتطلبات والخطوات وروابط التنفيذ الرسمية في رحلة واحدة. الإصدار 2.0 يطوّر المشروع من دليل إجراءات إلى طبقة تشغيل للبحث والتحقق والمحتوى والتسويق، مع إبقاء النشر الحكومي والتغييرات الحساسة تحت موافقة المالك.

> **تنبيه مهم:** خطوات ليست جهة حكومية ولا تنفذ المعاملة نيابةً عن المستخدم. أي معلومة متغيرة يجب أن تكون مرتبطة بمصدر رسمي وتاريخ تحقق قبل نشرها.

## ما الجديد في 2.0

### 1) واجهة عامة جديدة: Journey OS
- محور الصفحة الرئيسية: **«ماذا تريد أن تنجز؟»** بدل الصفحة التقليدية.
- عرض حي لرحلة الإجراء من الهدف إلى الجهات والمتطلبات والتنفيذ.
- قطاعات مبنية على نية المستخدم، تحديثات موثقة، حاسبات، محتوى، ومؤشرات ثقة.
- تصميم RTL متجاوب مع حركة هادفة واحترام `prefers-reduced-motion`.
- الصفحة العامة منفصلة بصريًا ووظيفيًا عن لوحة المالك، ولا يوجد مدخل إداري بارز في الواجهة العامة.

### 2) مركز عمليات AI
- وكيل إدارة مبني على **OpenAI Responses API** لأعمال البحث والتحليل والنمو وصياغة المسودات.
- وظائف إدارية مقيدة بالأدوات والصلاحيات، مع `audit_logs` لتتبع العمليات.
- لا تُنشر تغييرات حكومية جوهرية أو تغييرات حساسة تلقائيًا.
- الموصل القديم `AI_API_KEY` ما زال موجودًا للتوافق مع مولد المسودات/SEO السابق، بينما مركز العمليات الجديد يستخدم `OPENAI_API_KEY`.

### 3) السجل الوطني للمصادر
- سجل أساسي من **74 مصدرًا حكوميًا/تنظيميًا/منصة رسمية** موزعًا على القطاعات الرئيسية.
- تصنيف المصدر حسب دوره: مرجع، نظام/لائحة، صفحة خدمة، منصة تنفيذ، بيانات، تحقق، دليل.
- اكتشاف مصادر جديدة عبر **Exa** اختياريًا، مع OpenAI للتصنيف عند توفره.
- أي مصدر مكتشف آليًا يدخل كـ **مرشح** فقط، ولا ينتقل للمراقبة التشغيلية حتى يعتمد المالك.
- الاستفادة من نظام مراقبة المصادر الموجود أصلًا: يحفظ اللقطة والفرق ويُنشئ مسودة تغيير فقط.

### 4) أول رحلات إنتاجية موثقة
قاعدة البيانات المرفقة تنشر ثلاث رحلات مصدرية كبداية آمنة بدل إبقاء الخدمات التجريبية منشورة:
- قيد سجل تجاري لمؤسسة فردية — وزارة التجارة / المركز السعودي للأعمال.
- إصدار رخصة تجارية — وزارة البلديات والإسكان / بلدي.
- إصدار رخصة بناء — وزارة البلديات والإسكان / بلدي.

تم تحويل الخدمات التجريبية القديمة إلى مسودات غير قابلة للفهرسة. التوسع في الخدمات مصمم ليتم عبر خط التحقق والمصادر لا عبر توليد معلومات غير موثقة.

### 5) مركز التسويق AI
- إنشاء حملة من هدف + جمهور + عرض/رسالة.
- توليد مواد مخصصة لـ Google Ads وInstagram وTikTok وSnapchat وX وLinkedIn وYouTube وWhatsApp.
- دورة واضحة: **توليد → مراجعة → اعتماد → جدولة/إرسال → قياس**.
- لا يرسل النظام مادة خارجية قبل اعتمادها.
- يوجد موصل نشر موقّع HMAC إلى n8n أو Make أو عامل تكامل خاص، بحيث يمكن توصيل المنصات بدون وضع أسرارها في SQLite.

### 6) مركز التكاملات
السجل الحالي يضم 20 موصلًا قابلًا للتهيئة، تشمل:
OpenAI، Exa، Google Analytics، Search Console، Google Ads، Google Business Profile، Bing Webmaster Tools، AdSense، Monetag، YouTube، Meta، TikTok، Snapchat، X، LinkedIn، Pinterest، WhatsApp Business، Telegram، SMTP، وAutomation Bridge.

**مهم:** حالة `configured` تعني أن إعدادات الخادم المطلوبة موجودة؛ لا تعني أن OAuth أو موافقات الحساب الخارجي اكتملت تلقائيًا.

## البنية التقنية

- PHP 8.2+
- SQLite عبر PDO
- PHP server-rendered views
- Vanilla JavaScript/CSS
- pnpm **11.22.0** لبناء الأصول فقط
- قاعدة البيانات خارج `public/`
- لا توجد حاجة إلى Node/pnpm على خادم الإنتاج بعد بناء `public/assets/`

## متطلبات PHP

فعّل على Hostinger أو أي خادم إنتاج:
- `PDO`
- `pdo_sqlite`
- `mbstring`
- `curl`
- `openssl`
- `fileinfo`

قبل النشر:

```bash
php bin/check.php
```

## تثبيت جديد

1. ارفع المشروع خارج `public_html` إن أمكن، واجعل Document Root يشير إلى مجلد `public/`.
2. انسخ `.env.example` إلى `.env` وضع القيم الحقيقية على الخادم فقط.
3. أعطِ مستخدم PHP صلاحية الكتابة إلى:
   - `storage/database`
   - `storage/logs`
   - `storage/snapshots`
4. شغّل:

```bash
php bin/install.php
```

لإنشاء المالك بشكل آمن، ضع قبل التثبيت:

```env
OWNER_EMAIL=you@example.com
OWNER_PASSWORD=استخدم-كلمة-مرور-قوية-وفريدة
```

إذا لم تحددها، سيستخدم المثبت بيانات مؤقتة للتطوير فقط. **يجب تغيير كلمة المرور قبل نشر الموقع.**

## ترقية مشروع قائم إلى 2.0

خذ نسخة احتياطية إضافية أولًا، ثم نفّذ:

```bash
php bin/upgrade-v2.0.php
```

الترقية **إضافية وغير هدامة**: تنشئ الجداول/الأعمدة الجديدة عند الحاجة، وتأخذ نسخة احتياطية تلقائية من SQLite قبل التعديل، ثم تضيف السجل الوطني والتكاملات والبيانات الإنتاجية الأساسية.

## OpenAI Operations

ضع المفتاح واسم نموذج متاح في حسابك:

```env
OPENAI_API_KEY=...
OPENAI_MODEL=...
```

ثم من لوحة المالك > **التكاملات والمنصات** فعّل OpenAI. المفتاح لا يُخزن في SQLite.

الموصل المتقدم القديم للمسودات وSEO ما زال يستخدم:

```env
AI_API_KEY=...
```

وذلك للحفاظ على توافق الإصدارات السابقة. يمكن لاحقًا توحيد الموصلين بعد نقل جميع مهام المسودات إلى Responses API واختبارها.

## Exa لاكتشاف المصادر

اختياري:

```env
EXA_API_KEY=...
```

ثم يمكن تشغيل الاكتشاف يدويًا من لوحة المالك أو عبر Cron. Exa يستخدم للاكتشاف والبحث فقط؛ **لا يعتمد المصدر ولا ينشره تلقائيًا**.

## Cron المقترح

مراقبة الصفحات التشغيلية المعتمدة كل ساعة:

```cron
0 * * * * /usr/bin/php /path/to/khatauat/bin/cron-monitor.php >> /path/to/khatauat/storage/logs/cron-monitor.log 2>&1
```

اكتشاف مصادر مرشحة مرة يوميًا:

```cron
20 3 * * * /usr/bin/php /path/to/khatauat/bin/cron-source-discovery.php >> /path/to/khatauat/storage/logs/cron-source-discovery.log 2>&1
```

إرسال المواد التسويقية المجدولة كل 5 دقائق:

```cron
*/5 * * * * /usr/bin/php /path/to/khatauat/bin/cron-marketing.php >> /path/to/khatauat/storage/logs/cron-marketing.log 2>&1
```

## موصل التسويق إلى n8n / Make

من لوحة المالك > التكاملات > **Automation Bridge**:
- أدخل Webhook HTTPS عام وآمن.
- ضع السر في الخادم:

```env
AUTOMATION_WEBHOOK_SECRET=...
```

كل طلب نشر معتمد يتضمن:
- `X-Khatauat-Event: marketing.publish`
- `X-Khatauat-Signature: sha256=...`

على عامل التكامل التحقق من HMAC قبل أي نشر. لا تستخدم Webhook داخليًا أو `localhost`.

## Google / Meta / TikTok / Snapchat / X وغيرها

ملف `.env.example` يحتوي أسماء الأسرار المطلوبة. هذه الحزمة تجهز **طبقة التكامل والسجل والحالة وموصل النشر العام**، لكنها لا تستطيع إكمال موافقات OAuth نيابة عنك. كل منصة تحتاج تطبيقًا/حساب أعمال وصلاحيات بحسب سياساتها الحالية.

## SEO والقياس والإعلانات

المزايا السابقة محفوظة:
- canonical، sitemap، robots.
- Article وBreadcrumb Schema.
- GA4 بعد الموافقة.
- Google Search Console/Analytics قابلان للربط ضمن مركز التكاملات.
- AdSense وMonetag عبر مدير الإعلانات الموجود.
- لا توضع الإعلانات داخل الخطوات أو بجوار أزرار التنفيذ الحكومية بشكل يسبب التباسًا.

## الأمان والحوكمة

- CSRF للجلسات والطلبات الإدارية.
- Prepared statements عبر PDO.
- كلمات المرور بـ `password_hash`.
- أسرار API في متغيرات البيئة، لا SQLite.
- رؤوس أمان HTTP أساسية: HSTS عند HTTPS، `nosniff`، `SAMEORIGIN`، Referrer Policy، Permissions Policy.
- سجل تدقيق للعمليات الجديدة.
- النشر الحكومي والتغييرات الحساسة خلف موافقة المالك.
- موصل التسويق يرفض روابط Webhook غير HTTPS والعناوين المحلية/الخاصة.

## ما لا تدّعيه هذه النسخة

- ليست جهة حكومية ولا بوابة حكومية بديلة.
- لا تغطي آلاف الخدمات فعليًا بعد؛ هي الآن بنية إنتاجية للتوسع الموثق.
- الـ74 مصدرًا هي **نواة سجل** وليست ادعاءً بأنها كل مصدر سعودي موجود.
- وجود موصل اجتماعي لا يعني أن الحساب الخارجي متصل حتى تكتمل مفاتيحه/OAuth.
- AI لا يضمن صحة التغيير الحكومي وحده؛ المصدر الرسمي والمراجعة البشرية هما المرجع.
